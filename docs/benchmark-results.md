# Benchmark Results

## Run configuration

- Date: October 13, 2026
- Architecture: Apple Silicon `arm64`
- CPU count reported by macOS: 10
- Compiler: Apple clang 17.0.0.17000013
- CMake: 4.4.4
- Build type: Release
- Corpus: deterministic synthetic corpus generated by `search_benchmark`
- Documents: 2,000
- Query repetitions: 25
- Query: `search engine`
- Parallel worker count: 4

Run it from the repository root:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel
./build/search_benchmark
```

## Interpretation

- The linear engine has almost no build phase because it stores documents without preprocessing them. Its cost is paid during every query.
- The sequential indexed engine spends about 22.45 ms building postings before it can search.
- Four-worker indexed construction took about 6.61 ms in this run, approximately 3.4x faster than sequential indexed construction.
- Across 25 repeated queries, indexed lookup took about 0.19 ms compared with about 560.98 ms for the linear baseline in this run.
- The indexed query path was approximately 2,965x faster for this synthetic workload. This is a workload-specific observation, not a general guarantee.
- All implementations returned 3,350 total matches, which confirms that the optimization preserved the benchmark's expected behavior.

The results illustrate the central tradeoff: an inverted index performs more work and uses more memory up front, then makes repeated queries much cheaper. Parallel construction reduces part of that up-front cost, but its benefit depends on corpus size, document length, worker count, and hardware.

## Caveats

These are single-run measurements, not a statistically rigorous performance study. The corpus is synthetic and intentionally repetitive, and the benchmark does not yet measure peak memory, cold-cache behavior, confidence intervals, or multiple corpus sizes. Future benchmark work should add repeated runs, larger and less repetitive corpora, memory measurements, and a configurable workload.
